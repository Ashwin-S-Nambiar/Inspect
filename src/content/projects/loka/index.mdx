<Project /> is [Thoughtful Engineering](https://thoughtful.site)'s workspace for teams of AI coding agents. Each agent lives in a pixel town, keeps one long conversation, takes quests and opens the pull requests. The app and the server were already there when I joined, so my part was the way in: the landing, the sign-in pages, the docs and the 404. Inside the town I did a pass rather than a rebuild, and the iPhone and Mac apps got one too.

All of it went out in November 2026, on top of an upgrade to Next.js 16 and React 19.3 that came first.

The sign-in pages are their own layout at each size: a sheet over a short band of town on a phone, and two columns from desktop up.

## Reloading halfway down

The landing is long, and the first version had a bad reload: refresh partway down and the hero painted while the HTML streamed in, then the page jumped to where you were. The clouds shifted too, and the navbar faded a shadow in as you scrolled.

The first fix kept the scroll position per tab and held the body back until enough of the page had arrived to restore it in one frame. A day later the landing became prerendered and cached, each scene renders finished on the server and only starts playing once it scrolls into view, and stills sit under the live canvases so nothing pops in. The clouds are static now and the navbar keeps one border.

## A waitlist that never moves the page

Pro is a waitlist, and the form opens inside the Free and Pro card. The features list and the form share one grid cell, so the card never changes height and the section below never moves. The outgoing panel leaves in 150 ms, the incoming one starts 90 ms later and takes 350 ms, the same both ways. Not now or Esc closes it.

Reloading with the form open used to flash it shut and open again. A tiny script in the head sets the open state before the first paint:

```js
(function(){try{var h=location.hash;
  if(h==="#waitlist"||h==="#pro"||sessionStorage.getItem(KEY)==="open")
    document.documentElement.dataset.waitlist="open"}catch(e){}})();
```

## Docs that don't ship the docs

The docs share the landing's look, with search on Cmd K, an On this page list that follows you and a sidebar that hides on Cmd \\. The sidebar's state is a cookie the server reads, so a hidden sidebar renders hidden. An inline script would have been the usual fix, but React refuses to run one when the docs open from the landing page.

The first visit was slow because the nav, menu and search bundled every page and the changelog. Now they take an outline built on the server, the full-text index loads only when you search, and the pages are static. Every page shares one Pixelify font, so the docs stopped waiting on a stylesheet of their own.

## One kit for every window

Inside, every window was styled on its own. The pass put buttons, tabs, pills, modals and titles into shared primitives, a text scale into Tailwind, and one motion file so every window, modal and popover opens and closes the same way, reduced motion included. Menus, sidebars and the command palette share one highlight that glides between items, and the HUD fades pieces out instead of unmounting them, so windows open without a flicker. Agents got pixel portraits instead of emoji.

A later pass made buttons, loading and empty states consistent across the app and revamped the admin panel.

The SwiftUI app for iPhone and iPad got the same portraits and a calmer indigo accent, with Liquid Glass buttons and menus, long-press previews, zoom transitions and split views on iPad. The Mac app, a Tauri shell around the web build, got Settings on Cmd , and a Help menu that opens the docs, and its offline screen now matches the loading screen.

## Rough edges

- **Phones get a gate.** The town itself is a desktop app; on a phone /world points you to the app instead.
- **The landing is heavy.** The live town and the step inside tour make for a large page, which is why reloads needed the work above.
- **Open Loka is a full page load.** It skips client navigation because /world needs its own cross-origin headers.
